# LLA · 한국어 — specification and requirements

Purpose: a personal Korean-learning web app (installable PWA) for one user who is a **true beginner still learning Hangul**.
This document is written so that LLA can be rebuilt from scratch if every copy of the code were lost. It describes what the
current implementation does (verified against `index.html`, `lla_server.py`, `tools/import_story.py`), not wishes.
Operations (hosting, backup, rebuild) are in `README.md` and in the `mini-production` repo (`docs/RUNBOOK.md`).

## 1. Users, platforms, constraints
- One user. Used mainly on an iPhone (Safari, added to the home screen) and sometimes on a Mac browser.
- Works offline once loaded (service worker); needs the server only for sync.
- UI language: English labels, Korean content. No accounts, no logins: access control is the network (Tailscale tailnet only).
- Text-to-speech uses the browser's `speechSynthesis` with Korean voices (`lang ko-KR`); no audio files are stored.
- Hard rule from the user: never curate vocabulary away. Story imports must produce a card for **every** content word.

## 2. Architecture
| Part | Description |
|---|---|
| App | One static page `index.html` (about 2,500 lines of HTML, CSS, vanilla JS, no framework, no build step) + `sw.js` + `manifest.json` + `icon.svg` + `vocab.json` |
| Local state | Browser `localStorage` is the working copy (keys in section 7) |
| Server | `lla_server.py` (Python 3.9+, Flask): serves the allow-listed static files and `/api/data`, binds 127.0.0.1:8770 only |
| Storage | `data.json` in `LLA_DATA_DIR` (default `~/lla-data`): `{app, version, rev, updatedAt, cards, stories, settings}`; atomic writes, rolling `backups/` (last 50) |
| Sync | Manual buttons "Load from Mini" / "Save to Mini" with a revision check (details in section 6) |
| Transport | HTTPS by Tailscale Serve on the Mini (needed for the service worker); tailnet only |
| Seed | `cards.json` in the repo = first-start content when no `data.json` exists (224 cards) |

## 3. Functional requirements
### 3.1 Navigation
Four top-level tabs: **Vocabulary** (default), **Stories**, **Pronunciation**, plus the speed selector (Syllable, Slow, Normal, Fast; stored as `lla_rate`).

### 3.2 Pronunciation tab
Reference pages with tap-to-hear items: **Consonants**, **Vowels**, **Syllables**, **받침 Rules**. Built-in consonant/vowel cards are generated by `makeConCard` / `makeVowCard`.

### 3.3 Vocabulary tab (sub-tabs Add Card, Study, All Cards)
- **Add Card**: Korean word or phrase, meaning (English or Chinese), up to 3 example sentences, notes, tag, deck, level, pronunciation trap; a Naver dictionary lookup button; **Auto-fill** button (section 5).
- **Study**: spaced repetition. A queue of due cards (`nextReview <= now`), filters by tag and deck, flip to see the back, then rate with four buttons (below). Shows the next interval per rating.
- **All Cards**: list with filters (tag, deck), edit, delete, flip badges, and **auto-play** (carousel mode or full-card mode, interval configurable, pause/replay) that reads the filtered cards aloud in random order.
- Card fields: `id, korean, english, examples[], notes, tag, deck, level, trap, created, nextReview, interval, ease, reps`. Tags in use: `story`, `particle`, `grammar`, `number`, empty. Built-in reference cards use tags `particle` and `grammar`.
- **Scheduling** (`scheduleCard`, quality 0..3): 0 hard → interval 1 day, ease -0.2 (min 1.3); 1 ok → interval `max(2, round(interval * max(1, ease-0.5)))`, ease -0.1; 2 good → `max(3, round(interval*ease))`; 3 easy → `max(10, round(interval*ease*1.3))`, ease +0.1 (max 2.5). Then `nextReview = now + interval days`, `reps += 1`. New story cards start at `ease 2.0, interval 1, reps 0, nextReview = now` (so they are all due).
- **Meaning format (TTS-sensitive)**: `english` is `'<Hangul dictionary form>' (<word type>) <English meaning>`, e.g. `'걷다' (verb) to walk`. `speakMeaning()` sends the quoted part to the Korean voice and the rest to the English voice, so the quoted part must be pure Hangul (no romanization, no commas, no extra forms).

### 3.4 Stories tab (sub-tabs list, add, reader)
- **Add**: title, optional YouTube URL, pasted Korean text; "Import Story" asks Claude (`claude-haiku-4-5`, `max_tokens 4096`, called directly from the browser with the user's key) to split the text into sentences with English translations and to generate cards for every content word. Story shape: `{id, title, youtubeUrl, sentences:[{ko,en}], deck, created}`. The new deck equals the story title.
- **Reader**: each sentence shows Korean with every word tappable, English below, optional romanization toggle (`lla_story_roman`), copy-sentence button, **Print / Save as PDF**.
- **Word tap popup** (`findCardForToken`): looks the token up in this order: (1) exact card in the story's deck, (2) exact card in any deck, (3) prefix match in the story deck (noun + particle, e.g. 여행을 → 여행), (4) prefix match in any deck, (5) `vocab.json` alias bridge (conjugated form → dictionary-form card), (6) strip a grammar ending card (tag `grammar`/`particle`) and find stem+다 / stem+하다. If no card exists but the word is in `vocab.json`, a card is auto-created on the spot (lower quality: ease 2.5, no example, no deck). The popup also splits noun + particle visually (`tokenizeKo`), only when the bare noun exists as a card.
- Known words are highlighted; the popup can speak the word, show meaning, notes, particle explanation.

## 4. Card-writing rules (used by the story importer and the `/import` skill)
Decompose every space-delimited token into root + particles + endings + irregular rule (the `/morphology` skill holds the full table). Nouns/adverbs: `korean` is the bare dictionary form, particle named in `notes`. Verbs/adjectives: `korean` is the surface form as it appears, all layers decomposed in `notes`, irregular rule (ㄷ ㄹ ㅂ ㅎ 르 으) named. No cards for particles or pure endings (built-in reference cards exist). Skip nothing because it looks elementary.

## 5. Auto-fill
`autoFill()`: first looks the word up in `vocab.json` (exact entry or alias → `base`, builds conjugation notes via `buildConjugationNotes`); if absent, calls Claude (`claude-haiku-4-5`, `max_tokens 256`) for `{english, trap}`. `vocab.json` is a dictionary of about 1,750 entries: `{"가다": {"english": "(verb) to go", "trap": ""}, "가요": {"base": "가다"}}`.

## 6. API and sync
- `GET /api/data` → full document. `PUT /api/data` with `{baseRev, cards, stories, settings}`; requires header `X-LLA: 1` and `Content-Type: application/json` (cross-site requests cannot satisfy this without a preflight); validation: arrays of objects with `id`, settings keys allow-listed to `lla_rate, lla_ap_interval, lla_ap_mode, lla_story_roman` with string values (API keys and tokens are never accepted); `baseRev` must equal the server's current `rev`, else **409** (client says "Server has newer data, tap Load first"). Body limit 20 MB. `GET /healthz` → `ok`. Everything else is 404 except the static allow-list.
- **Load** merges the server data into local: server wins on the same `id`; local-only items stay, except a local-only card whose Korean text the server already has is dropped (`mergeCards`). Stores the revision in `lla_server_rev`. The app also loads once at start.
- **Save** refuses until a Load has happened; on success stores the new revision.
- Legacy path (to be retired): on `github.io` the same buttons use the GitHub API with a personal token.
- **Export / Import** (any origin): "Export all data" downloads and copies a JSON `{app:"LLA", version:1, cards, stories, settings}` (no keys); import by file or clipboard merges by `id` (imported wins).

## 7. Browser storage keys
`lla_cards`, `lla_stories`, `lla_rate`, `lla_ap_interval`, `lla_ap_mode`, `lla_story_roman`, `lla_server_rev`, and two secrets that exist only in the browser and are never synced: `lla_anthropic_key` (Auto-fill and story import), `lla_gh_token` (legacy only).

## 8. Offline / PWA
Manifest `LLA · 한국어`, standalone, theme `#1a4fa0`. Service worker `sw.js`: precaches shell files (`index.html, manifest.json, sw.js, icon.svg, vocab.json`), **network first** for same-origin requests with cache fallback; bump `CACHE` (`lla-vNN`) in every release that changes the shell.

## 9. Importing stories without the browser
`tools/import_story.py story.json [--dry-run]` writes a story and its cards through the API (validates Hangul in the quoted part of `english`, skips an existing title and any card whose Korean text exists in any deck, fills defaults, revision-checked save with one retry, idempotent). The `/import` skill (`.claude/commands/import.md`) produces the JSON from a YouTube transcript. After an import the user taps "Load from Mini".

## 10. Non-functional requirements
- No build step; the whole app must stay one HTML file plus the files above.
- Server tests (`tests/`, pytest) and a frontend syntax check run in CI on Python 3.9 and 3.12 (3.9 = the Mini's system Python).
- Data safety: atomic writes, rolling backups, hourly off-machine backup (see `mini-production`), no data in the code directory.
- Security: server binds loopback only; HTTPS via Tailscale; no secrets in git; API keys stay in the browser.

## 11. Dependencies
Server: `flask>=3.0` (`requirements.txt`); tests: `pytest>=8`. Client: none. External services used by the browser: Anthropic Messages API (`claude-haiku-4-5`, user's own key), Naver dictionary and Papago links.

## 12. Known gaps
Stories are only synced through Save/Load (no per-item deletion sync: a deleted card can reappear after a Load from a stale device); the Anthropic key must be re-entered per browser origin; GitHub Pages legacy mode still exists in the code.
